== What You've Learned

Across four modules you covered the complete operational update lifecycle for a RHEL image mode host:

* *Module 1 — Introduction to Image Mode Updates:* You confirmed the host is running in image mode, inspected the booted image and version marker with `bootc status`, and understood why image-based updates differ from in-place package patching. Updates are whole, versioned artifacts — not incremental changes to a running system.

* *Module 2 — Build and Push an Updated Image:* You built an updated bootc image from a Containerfile using Podman and pushed it to a container registry. The registry is the delivery mechanism: nothing reaches a host until an image lands there.

* *Module 3 — Configure Automatic Updates:* You enabled the `bootc-fetch-apply-updates` systemd timer and watched it fetch and apply the updated image without any manual intervention. Enabling the timer turns image delivery into a hands-off, scheduled operation across your fleet.

* *Module 4 — Roll Back a Failed Update:* You rolled the host back to its previous image with a single `bootc rollback` and confirmed the prior deployment was booted again. The previous image stays on disk after every update, making recovery predictable and fast.

The three skills at the center of this lab:

* Build a new bootc image and push it to a registry when you want to update the OS.
* Enable the `bootc-fetch-apply-updates` timer to automate image delivery on a schedule.
* Use `bootc rollback` to recover from a problem — no rebuilds, no backups, one command.
